# Анализ альфа-хвостов в .jpg (задача 31, пакет 5)

Дополнение к задаче 17 (`docs/open-questions.md`, пункт «Текстуры»): у 60 из 68 jpg
в `assets/textures` внутри файла лежит альфа-хвост оригинала
`[jpeg FFD9][w*h альфа][u32 count][0x6666]` (`NSOGLRender.dll`, `sub_10002190`).
На момент задачи 17 не извлечённых было 31; позже (пак 4, `EXTRA` в
`tools/extract_jpg_alpha.py`) 28 из них были извлечены, raw остались 3. Хвосты
сохраняются внутри всех .jpg, поэтому здесь проанализированы все 31 по исходному
списку задачи 17. `assets/` не менялся; превью — только в scratchpad//tmp.

Метод: `python3 tools/analyze_jpg_alpha.py` (read-only; `--all` — все 60,
`--preview DIR` — png-превью композита на шахматке и карты альфы).
Метрики: доли значений 255 / 0 / промежуточных (1..254), число различных
значений, bbox пикселей с альфой > 0, «подпись края» (промежуточные пиксели,
соседние и с 0, и с 255 = сглаженный контур; окружённые промежуточными =
обширная мягкая зона) и корреляция r(альфа, яркость jpeg) — ниже, в тексте.

## Что в альфе по группам

**Тайлы полей, 24 шт.** (`{grass,desert,swamp}_{up,down,left,right}_center` +
8 углов). Альфа — мягкий силуэт: 6–79 % полностью прозрачных пикселей,
10–17 % полутонов; «обширная мягкая зона» сильно преобладает над «краем»
(например, `swamp_left_center`: 360 краевых против 6625 мягких) — это не
сглаживание 1–2 px, а растушёвка силуэта забора и падающей тени. Корреляция
r(альфа, яркость) −0.76…−0.95: прозрачность растёт там, где jpeg темнее
(тень/фон вокруг забора). Композит на шахматке (превью) показывает мягкие
полупрозрачные тени под досками. Бинарная маска или color-key по чёрному
здесь дали бы грубый ореол — альфа настоящая, полупрозрачная.
Порт: извлечены в пак 4; сверка — альфа всех 28 извлечённых .png байт-в-байт
совпадает с хвостом исходного .jpg (проверено скриптом ниже, mismatch 0).
Рекомендация: **извлечение оправдано и уже сделано верно**.

**Грядки-подложки `beds_dry` / `beds_wet`.** 90 % непрозрачных, 8.8 % полутонов
(244 значения) — мягкая кромка по контуру грядки; r ≈ +0.11 (не привязана к
яркости). Извлечены, совпадают с хвостом. Рекомендация: извлечение оправдано
(мягкая кромка; color-key дал бы зубцы по краю).

**HUD-панели `upbar` / `downbar`.** `upbar` (1024×64): непрозрачная полоса
800×64 (правые 224 px — прозрачный запас, «align scalex» оригинала), 8.3 %
полутонов у краёв и в вырезах; скруглённые торцы. `downbar` (512×128): верхние
48 строк полностью прозрачны, затем 8 строк градиента 0→255 (каждая строка —
своя константа альфы: значения 3, 9, 18, 31, 45, 58, 72, 221 — по 0.77 %, т.е.
ровно по строке), нижние 72 строки непрозрачны — панель «выплывает» из-под
нижнего края экрана. Извлечены; `styles.css` уже учитывает прозрачный верх
(`downbar.png` со сдвигом `0 -50px`). Рекомендация: извлечение оправдано,
вставка верная.

**`item_shop_menu` (raw) — извлекать.** 64×128: две скруглённые панели 58×58
(верх — обычное состояние кнопки магазина, низ — нажатое/hover; прозрачные
уголки ~0.2 %). Но главное: панели не непрозрачные — 99.8 % пикселей имеют
альфу ≈ 75/255 (полупрозрачное стекло), кромка светлее (≈ 149–160), внутри
панели однородная полупрозрачность. Всего 65 различных значений — альфа
квантована, но точно не бинарная и не «всё 255». Порт использует эту текстуру
в `styles.css` (`.slot, .shop_item`, фон кнопок магазина, `58px 116px`),
сейчас — как .jpg без альфы: полупрозрачность и мягкие уголки теряются.
Рекомендация: **извлечь** (перезаписать в .png с альфой, обновить манифест и
URL в `styles.css`). Внимание: при вставке в CSS полупрозрачный фон кнопок
должен ложиться на панель игры, как в оригинале, — проверить визуально.

**`shop_item` (raw) — извлекать, но порт пока не использует.** 64×64: одна
скруглённая полупрозрачная панель; её хвост байт-в-байт совпадает с первыми
4096 байтами хвоста `item_shop_menu` (это верхняя панель той же текстуры —
в `texturehost_scripts.txt` обе лежат рядом, оригинал использовал `shop_item`
как отдельную ячейку). В порте ключ есть в манифесте, но ни `src/`, ни
`styles.css` на него не ссылаются. Рекомендация: **извлечь** (дешёво, хвост
уже в файле, манифест тогда укажет на .png); альтернатива — не трогать, пока
порт не начнёт использовать текстуру, т.к. визуального эффекта в порте нет.
Делать то или другое, но не оставить raw-состояние: при будущем использовании
.jpg снова потеряет полупрозрачность.

**`mask_upbar` (raw) — порту не нужен, извлечение не требуется.** 256×64:
72 % значений 255, 10.8 % нулей, мягкие скруглённые торцы; r(альфа, яркость)
= +1.00 — альфа в точности повторяет яркость jpeg-части (13467 из 16384 байт
совпадают с `Image.convert("L")`, остальные отличаются на ±1–2 из-за декодера
— маска была сгенерирована из яркости самой картинки). В оригинале это
`tex_mask_name` окна `upmenu_form` (`menuhost_scripts.txt:216`) — маска
верхней панели меню/уровня. Порт рисует верхнюю панель DOM-элементом
`#topbar` c уже альфированным `upbar.png`, маску не использует и в скриптах
не читает. Рекомендация: **не извлекать** (если однажды порт возьмёт
`tex_mask_name`, альфа достаётся тем же механизмом из хвоста).
